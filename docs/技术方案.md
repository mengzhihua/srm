# SRM 技术方案

SRM 走采购协同：采购申请、询价、采购订单、ASN、收货和供应商考核。与 WMS 同步入库，与 SAP 模拟过账。IR 拉单据快照，并下发采购建议、提交、审批和催单。

## 1. 运行位置

| 场景 | 后端 | 说明 |
| --- | --- | --- |
| 单机 | `8081` | `application.yml`，前端开发 `5174` |
| 与控制塔同机 | `8087` | IR `ct_system` 种子 |

Open IR 使用 `X-Api-Key`。控制塔种子键是 `srm-wms-key`，与 WMS 回传共用这把键。登录业务口使用种子账号 `admin / admin123`。

## 2. 主链路

```text
PR → RFQ → PO → 下发 SAP → 供应商确认 → ASN → WMS 收货
    → GR / 模拟 MIGO → 考核 → 发票三单匹配
```

`GET /api/open/ir/match-basis?poCode=` 给出订单金额、已收数量和最近收货单，供进项三单匹配使用。没有收货单时已收数量取订单行。下发 WMS 时供应商必须有 WMS 供应商编码，`SUP03` 没有映射，http 模式会直接失败。

## 3. 控制塔读

`GET /api/open/ir/snapshots` 的 `snapshots` 行：

| dataType | 业务键 |
| --- | --- |
| `PR` | 采购申请号 |
| `PO` | 采购订单号 |
| `ASN` | 发货通知号 |
| `SUPPLIER` | 供应商编码 |

没有 Key 时，控制塔改拉采购订单、ASN 和评估分页。

## 4. 控制塔写

`POST /api/open/ir/actions` 的请求体是采购建议结构（含 `type`、`targetKey`、`sku`、`qty`、`code`、`poCode`）。统一口不可用时回退专用口。

| 指令 | 专用口 | 作用 |
| --- | --- | --- |
| `SRM_PURCHASE_SUGGEST` | `POST /api/open/ir/purchase-suggest` | 按 SKU、数量、工厂生成采购申请 |
| `SRM_SUBMIT_PR` | `/submit-pr` | 按申请号提交 |
| `SRM_APPROVE_PR` | `/approve-pr` | 按申请号审批 |
| `SRM_EXPEDITE_PO` | `/expedite-po` | 按采购订单号催单 |

没有 API Key 时，控制塔登录后：

- 采购建议：`POST /api/sourcing/pr`，默认再 `/{id}/submit`
- 提交 / 审批：按申请号查出 id，`POST /api/sourcing/pr/{id}/submit|approve`
- 催单：按采购订单号查出 id，`PUT /api/purchase/order/{id}`

非空幂等键按 `type|业务键|key` 缓存。

## 5. 边界

控制塔不在 SRM 里做询价和三单匹配。采购建议生成的是申请草稿或已提交申请，不是已经发给供应商的订单。

`SRM_SAP_MODE=ecosystem` 时，采购订单、收货和发票打到本套 SAP 演示的 `/api/mm/*`，不再生成 `50xxxxxxxx` 模拟凭证。`http` 仍是 S/4 OData。物料必须能在 SAP 主数据中找到。
